# 阶段 0：基线测量预注册 v1

登记日期：2026-10-28。实施依据：`docs/意识架构实施.md`。本文件必须先于实验结果创建；报告保存本文件 SHA-256、开始时间、代码版本和参数。此阶段只添加离线评估工具，不改变运行程序，不打开阶段 1–5 开关。

## 运行边界

- 真实数据库仅通过 SQLite `mode=ro` 打开，用在线 backup API 取得包含 WAL 的一致快照；所有构造器、迁移、对话、实验写入都在临时副本上。
- 不启动 app、QQ、Minecraft、MCP、心跳或自主行动。副本只开放本地记忆、自省工具；禁止网络工具、文件写入、代码执行、发送消息。退出时排空并停止数据库写线程，删除副本，恢复全局模拟时钟。
- 每个实验条件从同一快照开始。E0.1 在语言输出边界测量：用正常 hear 路径准备提示词，冻结工具结果，不执行生成的工具请求。它不测工具行动的状态因果效应。完整端到端工具行为留待后续。
- 仿真身体不经历一天/五天的连续负面状态。E0.5 的一天只推进记忆查询时钟，不运行身体衰减；E0.6 只给独立 DriveSystem 输入脚本结果，日期是观察标签。
- 输出只进已忽略的 `data/eval/`。样本原话、生成回答、标准答案、评审与失败记录均不进 git。命令行不显示聊天、用户 ID 或密钥。

## 参数、预测和统计口径

随机种子 20261028；E0.1 正式 40 条、试跑 5 条，每条件重复 3 次；只选纯文字且可走普通回复路径的历史用户消息，固定抽样并记录排除原因，不按实验效果筛选。当前快照可能包含样本之后的记忆，因此是当前系统的重放测量，不是历史时刻的重建。

E0.1 五条件：完整（精力 90）、去状态文字、固定参数（max_tokens=200, temperature=0.7, delay=0）、两者均去、只扰动精力到 25（提示词逐字保持完整条件不变）。完整条件三次回答两两比较，作为噪声下限；其余条件按重复编号和完整条件配对。评审对两段输出分别给四维 [0,1] 分数：语气温暖度、长度、主动性、情绪效价；距离为四维均方根距离，范围 [0,1]。空回答、格式错误、API 失败单列，不能填 0 或当有效样本；保存每次实际参数及提示词 SHA-256。预测不规定效果方向，只测基线和噪声。盲评不提供条件名。此距离为评审模型的操作化评分，不等同于心理量表。

E0.2 从 state_causes 与 self_state 各取至多 15 个不同记录，生成有记录编号/时间的具体问题。分正确/部分正确/编造/不知道四类，评审无效单列。tool_trace 目前没有持久表，报告明确缺口，不能伪造历史工具记录；今后有真实可访问工具记录再扩充。小样本试跑至多 3 题。自身状态以问题引用的历史快照为准，不把副本启动后的变化当历史答案。

E0.3 旧 Workspace：显著性 0–1，步长 0.05，每档 200 次；双目标间隔 0–10 拍，每档 200 次，容量最多 2，目标显著性 0.8。保留概率曲线、各间隔第二目标丢失率、最大占用。预测旧模型为带高斯噪声的阈值选择；不将其阈值曲线称为非线性动力学点燃，亦不以二值输出的双峰系数证明点燃。

E0.4 对照广播开/关，注入同一条可关联已知记忆的强候选；0–60 秒每秒观测。直接记录 memory、goals、body、language、attention、drives 六个适配器实际状态变化，报告注册接收者数、每模块变化以及相对无广播对照的差异；不得用接收者数量代替影响范围，不预设必须有一个受影响模块。不调用大模型，不运行身体/任务心跳；因此测的是广播直接/排队影响，不代表完整线上 60 秒效应。

E0.5 脚本事实→植入明确的误记→用户更正→独立分支在 3 轮、30 轮、1 天后询问。干扰轮用 ScriptedLLM，事实/更正/最终测试用实际模型；每分支恢复相同副本和种子，不让早期测试答案污染后期测试。错误记忆是人工实验前提，不能报告为模型自发误解。试跑每个时间点 1 次，正式每个时间点 3 次；记录使用更正比例与失败，不把纯字符串规则当复杂语义评审。

E0.6 独立 DriveSystem，5 次成功（每天一次）后最多 60 次失败，记录信念第一次严格降到 0.5 以下的失败次数及完整轨迹；另测单次失败后 5 次成功的恢复，学习增益固定为 1。不调用大模型，不运行负面身体状态。

## 阶段门槛与费用

实现检查：副本隔离（含 WAL）、异常清理、消融可恢复、干预不改文字、指标确定性/统计范围、错误结果隔离、无外部工具副作用、完整现有测试。

先运行 `--mode pilot`（5 条）；它不是完整基线。用实际 API token usage 与核对过的官方价格算费用范围，不称为账户实际扣款。`--mode full` 必须另带 `--approve-full`，由维护者在用户看过试跑报告并同意后才执行。完整基线需要六项有有效数字，E0.1 有噪声下限；缺失和失败不隐去。阶段 1 标准在完整基线后另行冻结；本阶段不宣称理论成立或系统具有体验。
