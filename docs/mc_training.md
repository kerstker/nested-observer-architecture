# 乃爱 Minecraft 训练与验收：第一阶段

目标：在陌生场景完成准备、出门、采集、处理意外、返家、存储。当前工作是建立可核验的基础，不代表已经完成这个综合目标。

## 当前实现

- 后台技能开始时清空上一任务的局部作业结果，防止旧进展或旧失败原因污染新任务。
- 每项后台技能记录开始/结束时间、有限的参数、前后坐标/维度/生命/饱食/物品数量，以及结构化判定。物品统计包含盔甲和副手，但不重复计算主手。
- `completed`、`partial`、`failed`、`interrupted`、`unverified` 分开记录。已有文字结果只保留为尚未覆盖技能的旧调度提示，不能充当训练完成证据。
- 合成以目标物品净增加数量验证；物品目标以实际持有量验证；移动以同维度的水平距离和高度差验证；放置以技能实际观测到的目标位置事实验证。
- `go_home` 的合同只验证到家，**不证明随后的存储或整个采集返家任务完成**。`collect_drops` 的入包证据只证明部分拾取，不保证清空附近全部掉落物。挖矿、建屋、战斗、存储等其余技能尚需补专门的完成合同，不按文字自动判为完成。
- 拾取回复不再把走近物品算作拾取成功。物品目标规划承认已经装备的目标，其他穿戴物品不进入合成原料池。
- 实机记录发现铁锭目标反复尝试未实际下降的楼梯。直接目标入口现在也检查失败冷却，避免从 `mc_goal` 或旧调度分支绕过退避。身体到达水平目标后允许最多一秒等待真实落地，仍保留原有高度误差限制，不把等待本身当作到达。
- 控制台 `/console/api/outside` 的 `game.training` 提供最近 64 项结果。此接口不额外查询游戏，也不公开聊天、用户身份、内部独白或令牌。记录器不保存整个控制台响应。
- 前后观测是依次进行的 RPC，非原子世界快照；背包净变化是观测证据，不能在多人赠物等干扰下单独证明因果。正式考试需要控制这些条件。

## 运行只读记录器

在项目根目录执行，输出目录必须是新的，避免覆盖已有记录：

```powershell
python -X utf8 scripts/record_mc_training.py --seconds 180 --output output/mc-training-run-001
```

输出 `samples.jsonl`（时间序列）、`actions.jsonl`（本次录制期间结束的任务）和 `summary.json`。读取现有公开快照和本机认证控制台，不依赖 8765 直播服务，不发送游戏命令，不读写生产数据库。

旧进程没有 `game.training` 时仍可采集身体基线，但动作覆盖率和完成率不可得。修改必须由新进程加载后才能记录结构化动作。历史环形缓存并非持久录像：记录器应覆盖整场考试，若停录或超过 64 个结果未采样，会缺失数据。

`stationary_walk_review` 只提示连续行走却长时间停留在小范围的片段，需画面与动作记录复核；它不能检测所有绕圈、目标反复或无效采集。`qualification=not_assessed` 表示采样结果从不自动授予高手资格。

## 课程与门槛（待实机执行）

| 课程 | 场景变化 | 实际证据 |
| --- | --- | --- |
| 移动返程 | 门、台阶、高差、绕障碍、路径被堵 | 同维度实际到达；中断释放输入 |
| 进食 | 容器旁、主副手、使用中断 | 物品消耗与饱食/使用状态；不能靠时长 |
| 采集拾取 | 遮挡、不同工具、背包满、掉落物不可达 | 方块变化与目标物品入包分别验证 |
| 放置 | 不同附着面、距离、占位 | 正确位置、方块及所需朝向 |
| 制作存取 | 材料缺失、容器满、已装备目标 | 材料与产物变化；箱子和背包双向核对 |
| 中断恢复 | 受伤、低饱食、断工具、失联 | 原动作结束、避险、恢复或明确退出 |

初步每项至少 20 次跨场景试验，建议完成率达到 95%，并无假成功；危险行为不能只按平均值放行。训练场与未见过的考试场分开。指标包含失败、中断和无法核验，不能只挑成功片段。模拟测试通过不等于实机合格。

基础技能合格后再做综合任务；必须单独证明采集、到家和存储三部分。用相同版本、资源和观察权限下的真人记录建立基线。一次修改前后保留相同测试条件、源文件哈希、回归结果与实机证据。
