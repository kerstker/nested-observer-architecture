# 多步规划、反馈学习与执行验收

本轮在 `1bb06f2` 的测量模块之外接入了真正影响路径选择的规划器。它面向有明确整数状态、资源依赖、目标和动作契约的任务，支持 16 步、最多 20,000 个节点预算。它不能保证一般自然语言任务已被正确形式化，也不等于未知世界的通用动力学模型。

`plan_actions` 生成多步动作及各步预测状态；执行必须继续使用原有权限检查的工具。`observe_plan` 接收逐步实际状态，核对顺序、报告预测误差，偏差出现时终止旧预测并要求重规划。只有观察到目标达到才积累该段解法。反馈不自动识别因果来源。

学习模型按动作和提供的自身状态维护 Beta 转移预测匹配计数，以及最多四种实际状态增量及其频次，模型训练直接来自实际反馈。多步预测使用观测到的常见状态增量，路由使用转移预测匹配概率折算动作成本，因此经验能够改变下一次路径。未见自身状态采用独立先验，避免把低资源条件下的失败直接推广到高资源条件。该模型属于轻量统计学习；本轮没有训练基座模型、神经世界模型或 LoRA。

解法库按授权作用域、动作契约和目标隔离，复用前逐步重新验证。更改动作成本或效果会更改域标识。解法和聚合模型随正常状态快照恢复；包含私人完整状态的待执行计划不会跨重启恢复，以免重复执行。库和待执行计划各有容量上限。

真实文件评测使用临时目录中的文件制作、依赖读取和 SHA-256 校验作为外部完成判据。各模型分别在 20 个训练任务之后，在 60 个新文件内容上比较四种方法：

| 方法 | 完成率 | 平均动作成本 |
| --- | --- | --- |
| 学习后的自适应规划 | 100% | 1.6 |
| 去掉自身状态的学习规划 | 100% | 2.0 |
| 固定快路径 | 50% | 3.2 |
| 已知故障条件的简单规则 | 100% | 1.6 |

这里的低能量执行故障由评测器控制，动作成本为预设单位，不是 API 费用或端到端耗时。该结果检验闭环接线、反馈利用和实际文件完成情况，不能证明比强规则基线更优，不能证明通用智能达到最先进水平。评测脚本为 `scripts/evaluate_planning.py`，逐题记录为 `closed-loop-file-evaluation.json`。

工程接入与科学结论必须分别验收：已实现受限任务的多步预测、反馈更新、重规划和解法积累；开放世界未知动力学、语言模型对照、因果识别和大规模排行榜验证仍属研究工作。缺少这些证据时，不应把全部工程工作完成写成全部研究命题成立。
