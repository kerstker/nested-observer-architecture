## 启用和回退

示例配置新增两个显式开关：

```json
{
  "CORE_LOOP_ENABLED": false,
  "WELFARE_GUARD_ENABLED": false
}
```

在独立测试实例中同时设为 `true` 才启用核心循环。运行实例在下次启动读取配置；本次集成不修改部署配置、不重启应用。核心循环不能在缺少恢复监控时启动。

首次启用前必须完成 `BackupManager.run(reason="pre-stage-1")` 且返回成功，之后才添加 `self_state.core` 和恢复事件表。已有数据库和旧状态兼容；关闭开关时不迁移数据库。关闭核心循环会恢复原工具轮数、工作空间阈值、召回偏置和负面情绪衰减倍率。

需求增长按身体实际更新时间估计，满足需求不会被外推为持续下降；失去观测、时钟倒退及重新启用会清空过时速度。恢复监控也不把暂停期间当成连续低值证据。工具权限和自主行动冷却保持原设置。

控制台新增只读、受原有鉴权保护的 `/console/api/core`，展示已存快照与恢复事件。

## 质量优先的自我改进

旧逻辑可能接受“耗时 10 → 5 秒、准确率 0.95 → 0.80”的候选，因为指定耗时指标变好；也可能被新通过的场景掩盖其他指标退步。可复现案例及修复前后判断见 [quality-gate-regression.json](quality-gate-regression.json)。

新逻辑先要求：非空且相同的场景/种子集合、相同指标及其样本覆盖、有效的两侧基线、有限数值、没有已通过场景退步，也没有超过允许幅度的指标退步。之后才判断新通过场景和目标增益。

默认保留原来的 5% 相对变化阈值，但它现在对全部已登记指标生效。更严格的任务可事先指定绝对质量容差，例如：

```python
report = fitness.compare(
    before, after, target="seconds",
    directions={"accuracy": "higher", "ce": "lower", "seconds": "lower"},
    quality_tolerances={"accuracy": 0.002, "ce": 0.01},
)
```

缺少必需质量指标直接拒绝。这是工程验收器，不计算统计显著性或置信区间；正式研究仍须事先锁定样本、门槛、对照和完整成本口径。耗时指标应包括读取、初始化、推理、验证及需要摊销的开发费用，不能只报内循环速度。
