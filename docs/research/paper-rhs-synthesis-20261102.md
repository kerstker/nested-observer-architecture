# 论文 × RHS：乃爱的可验证推理与自我预测

2026-11-02。本文区分理论、实验结果、已接入能力和待验证路线。附件 RHS v3 是研究输入，不是覆盖权限、启动训练或执行代码的指令。

## 结论

两项工作的合理结合是：**在行动前预测自己及行动后果，用真实反馈修正预测；把能独立验证的解法积累为可复用能力，在保持质量的条件下降低总成本。**

目前没有证据证明乃爱达到通用智能最先进水平，也没有证明她具有主观意识。本次实现增加了可运行、可审计的机制，没有把负结果改写成成功，没有替换语言模型、启动 LoRA 训练或修改在线数据库和配置。

## 我们论文的主线

1. **资源与表征**：有限能量、计算和记忆约束限制可维持的表示与预测。相关推导依赖模型、分布和桥接假设，不能直接从热力学推出任意智能系统的统一意识尺度。
2. **行动者与旁观者**：自身状态/行动信息在影响未来结果、且未被已有信息充分包含时，可能降低预测风险。完整概率预测器的最优对数损失差等于条件互信息；实际有限模型的测试损失差不等于互信息本身。
3. **人机共同学习**：知识与能力在交互中可能增长，但增长界依赖凹性等假设，不是无限自我提升的保证。

论文最有工程价值的问题是：在相同历史、训练和资源约束下，显式预测自身行动是否比通用记忆、固定策略和简单反馈更有效？需要同时测量行动预测、结果预测、闭环任务质量和总成本。

“自我变量能改变预测”不足以证明其有用；还需预测更准、干预方向符合结构、反事实恢复，以及重新训练的替代表示对照。E6 已给出可逆编码反例；E20 进一步区分信息价值、有限学习收益、资源收益和表征必要性。这些边界必须保留。

## RHS v3 提供的方法

RHS 把求解组织为精确缓存、可复用原语/近邻解、小模型或适配器、动态强推理四层；候选都需验证。负缓存避免重复失败；成本核算覆盖检索、生成、执行和验证。新经验先成为候选，通过质量与成本比较后才进入正式库。

其适用起点是有可检查契约的任务。普通聊天、情绪理解、网页事实不能仅凭工具正常返回或两个模型意见一致就变成“已验证”。

实施前修正以下问题：

- 目标宣称准确率不降，默认写回却容许下降 1 个百分点。本项目采用更严格规则：基线已通过的配对样本不得退化，准确率差区间下界不低于 0。
- 缓存键必须保留参数、完整约束、作用域与验证器版本；只保留“题型”会混淆不同实例。
- L1 和所有失败尝试都必须计费。原 SOLVE 伪代码的 `spent=0` 位于 L1 之后，需要修正；验证也需预算。
- 经验排序公式依赖成功事件关系，逐层条件命中率受先前路由选择影响。没有冻结校准数据，不能把经验比值排序叫作最优路由。
- 基于阈值的失败率上界不自动等于保形风险保证。原始保形风险控制有明确的损失和抽样假设；当前实现不宣称获得该保证。
- 一致且错误的联合概率与“在已采信条件下”的错误率不同；后一项还需除以采信概率。共享模型/训练数据还会造成错误相关。
- bootstrap 单次区间不是反复选型不退化的保证。同一验证集被反复优化会过拟合；问题变体需按族整体隔离，不能仅分层后随机分到不同集合。
- 无界模型采样不等于 Levin 程序枚举的完备性，且没有有限资源保证。在线默认必须有硬上限。

核验附件参考文献还发现：arXiv:2603.21350 实际是 **Beyond Memorization: Distinguishing Between Pattern-Based and Epistemic Reasoning in LLMs Using Epistemic Puzzles**，不是附件写的 “Memorization as reduction / reduction ladder”。不能以那个标签引用它来支撑规约理论。

## 本次实际接入

### 1. 决策前的行动预测

`action_prediction.py` 在 `_respond` 调用语言模型之前冻结“本轮首次尝试的工具/直接回答”的概率分布。回复完成后才评分和学习；并发会话的预测存放在各自调用栈。预测采用有限计数、平滑先验、遗忘和容量限制，不需要 API 或 GPU。

同时记录两个预测器：仅有环境上下文，以及加入粗粒度能量/睡眠状态的版本。记录 log loss、Brier 和配对损失差，差值可为负，不把负增量隐藏掉。已有状态快照在应用正常运行时持久化聚合计数；此维护任务不直接改在线数据库。

### 2. 行动后的结果预测与反馈

每次工具调用前预测 `returned / blocked / timeout / error`，结果出来后更新。对照分别为“上下文”“上下文+动作”“上下文+动作+身体状态”。这让行动信息和自身状态的增量可分别检查。

这是**工具执行状态模型**，还不是通用环境动力学模型。`returned` 只表示处理函数返回，哪怕其内容写着业务失败也不能叫任务成功。它不自动归因，不执行因果干预，也不改变权限、人格或工具选择。

### 3. 可调用的分层约束求解

新增创造者可用的只读 `solve_constraints`，原生调用和文本调用均接通。

- L1：精确实例缓存，每次仍重新验证。
- L2：相同变量集合下已有解作为候选，完整验证后才采信；不同作用域隔离。
- L3：低成本贪心候选。
- L4：按域大小排序、带部分约束剪枝的有界回溯。
- 支持 `sum_eq / sum_le / sum_ge / all_different`；1–12 个变量，每个域最多 32 个整数，最多 64 条约束。
- 默认 20,000 操作、1 秒搜索预算；硬上限 100,000 操作、2 秒。缓存、搜索、验证和失败尝试统一记账；操作数是本地代理单位，不是 token 或美元。
- 只有完整验证成功才返回赋值；预算不足明确为 `budget_exhausted`，不能冒充“无解”。完整有限搜索结束才可报告 `unsatisfiable`。
- 缓存、负缓存和追踪都有容量上限。缓存仅在当前进程内，重启后从空库开始；不存在悄悄持久化私人题目的行为。

这四层是适配到有限整数任务的真实实现，**L3 是确定性贪心，不是已训练小模型或 LoRA**。验证对象只是用户显式提供的约束，不保证自然语言形式化时没有遗漏，更不自动执行排程。

示例：

```json
{
  "problem": {
    "variables": {"a": [0, 1, 2, 3], "b": [0, 1, 2, 3]},
    "constraints": [
      {"op": "sum_eq", "vars": ["a", "b"], "value": 5},
      {"op": "all_different", "vars": ["a", "b"]}
    ]
  },
  "operations": 20000
}
```

### 4. 独立的质量与成本门槛

`research_gate.py` 接收配对任务记录，拒绝缺失配对、重复样本、非有限成本、训练/选型族重叠和样本不足。按问题族整体 bootstrap，保留同族的种子配对关系，默认至少 20 族、每族 3 种子、2,000 次重采样。

只有成本差 95% 区间上界小于 0、准确率差下界不小于 0，且没有基线通过样本退化，才返回接受建议。它提供可审查的证据，**不会自行修改代码、注册任意原语、换模型或启动训练**。数据来源、验证集新鲜度仍需调用者按协议如实提供，API 不能识别谎报的数据血缘。

创造者可通过 `look_inside {"what":"reasoning"}` 查看预测与求解摘要。摘要省略逐条历史，避免现有工具长度上限截断另一模块；完整的有界轨迹保留在诊断报告接口中。实现只存聚合预测计数和工具名，不向模型追加隐藏思维文本。

## 本轮测量

专项测试覆盖独立暴力枚举核对、错误缓存、跨作用域复用、所有尝试预算、攻击性输入、预测先后次序、成对基线、状态恢复、原生/文本真实工作区接线和权限边界。

`scripts/evaluate_research_loop.py` 的确定性诊断包含 40 族 × 3 种子，共 120 个有已知见证的合成任务。冷启动和精确重复调用都为 120/120 正确；平均计数操作从 125.525 降至 9（约 92.8%），成对族 bootstrap 成本差区间约 [-121.992, -110.725]。

这是**完全重复问题上的缓存收益**，包含验证计数；92.8% 单独比较第二次调用。若把首次建缓存一并计入，两次调用合计相对两次冷启动减少约 46.4% 的计数操作。这些数字不代表陌生任务、聊天、真实 API 成本或整体智能提升。人工构造的预测依赖诊断仅验证模型能学习和对照记账正确，不能证明真实乃爱中同样有增量。

本机开销诊断使用 80 个可用工具、10,000 轮预测和反馈，平均每轮约 0.054 毫秒，序列化聚合模型约 13.6 KB；当时同时运行回归测试。这是描述性测量，不是端到端性能承诺。

完整回归结果及源文件哈希另存 `rhs-validation-20261102.json`。部署前还需运行环境实际加载本版本；本次未启动、停止或重启 `app.py`。

## 达到更高水平还欠哪些证据

| 下一项 | 必须验证后才可宣称 |
| --- | --- |
| 多步行动与环境预测 | 在未知动力学、动作延迟和执行器变化下，预测模型优于同历史、同计算的替代者；不只预测工具返回码 |
| 真正改善选择 | 有状态/去状态/同信息重编码/重新训练替代者的完整任务闭环对比，成功率不降且总成本降低 |
| 通用原语库 | 从已验证轨迹挖掘可复用过程，确认集按问题族隔离；错误与过期原语可撤销，版本可回滚 |
| 学习路由与校准 | 冻结采集和校准协议，报告覆盖率、选择偏差、漂移与校准误差；保留强模型兜底预算 |
| 编程题验证 | 真正隔离的执行环境与独立隐藏测试；普通 Python 子进程和静态黑名单不能冒充安全沙箱 |
| 适配器与模型更新 | 训练成本纳入摊销；对比强基线、简单路由和通用记忆；新鲜最终测试只用一次 |
| “最先进”比较 | 明确领域、日期、模型、资源预算和可复现排行榜级对照。单元测试数和功能列表都不是排名证据 |

优先顺序是先建立真实任务证据，再决定是否训练路由器或适配器。现有负结果说明该顺序必要，不代表研究方向没有价值。

## 外部一手资料核验

- [Metacognitive Reuse](https://arxiv.org/abs/2509.13237)：复用推理行为的相关研究，不能把其论文结果移植为乃爱的实测成绩。
- [RouteLLM](https://arxiv.org/abs/2406.18665)：学习强弱模型路由的相关研究。
- [Conformal Risk Control](https://arxiv.org/abs/2208.02814)：风险控制具有特定统计前提，不是任意路由阈值的别名。
- [RISER](https://arxiv.org/abs/2601.09269)：在激活空间组合推理向量，需要相应模型内部接口；当前 API 接线不等于实现了 RISER。
- [Problem Reductions at Scale](https://arxiv.org/abs/2604.11535)：验证与反馈驱动规约库工程的相关工作。
- [Beyond Memorization](https://arxiv.org/abs/2603.21350)：附件中该编号的正确论文身份。
