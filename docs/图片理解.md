# 图片理解：只走 API（本地视觉已删除）

2026-10-25。原先她的"视觉"是本机的 DeepSeek-VL2-Tiny（`scripts/senses/see_server.py`，`:8092`）：
先把图看成一句 120 字的中文描述，再把这句话塞进消息文本里。这套东西一直没跑起来
（xformers/torch 版本不匹配、进程启动后又退出），却占着 `.venv-vision`（3.1 GB）和
`models/deepseek-vl2-tiny`（6.3 GB）。

现在：**图片原样交给模型，跟着这条消息一起进主对话**——她读消息时图就在眼前，不用先经过转述。
本地视觉整条链路（服务、venv、模型、源码、启动脚本里的 sight 部分）已删除。

## 链路

```
app.py  custom_message_handler
   ├─ qq.media(segments, limit=VISION_MAX_IMAGES)   图片段 -> {"data": bytes, "mime": ...}
   ├─ qq.perceive(..., look=True)                   文字部分照旧（OCR、语音、引用、转发…）
   └─ global_workspace.hear(..., media=media)
        └─ process_input(..., media)
             ├─ _construct_prompt(..., media)       user 轮末尾注明"这条消息带了 N 张图"
             └─ _generate_response(..., media)
                  └─ _llm(prompt, media=..., **params)      # 只把引擎认识的参数传下去
                       └─ DeepSeekEngine.generate_json(media=...)
                            └─ with_media()：把图作为 image_url 内容块挂到最后一个 user 轮
```

- 只把**当前这条消息**里的图原样挂进主对话；引用消息里的图挂不进去，由同一个 DS API 描述一句
  （只在她在意时调用，有缓存）。转发聊天记录里的图不描述，避免一条转发触发很多次 API 调用。
- 图片不落盘、不进记忆：只有她由此说出来的话会变成记忆（和以前一样）。
- 引擎声明 `supports_images`：`deepseek` 为 True；`hybrid` 的本地 LoRA 为 False，但它带着远程
  DeepSeek 那一半，所以会话里的图仍由远程 API 描述后喂给本地模型；只有 `local`（纯 llama.cpp、
  完全没接 API）才会只知道"来了一张图"（QQ 的 OCR 仍会读出图上的字）。
- 失败一律软处理：下载失败、没有 Key、API 报错 → 她只知道"来了一张图"，不假装看见。

## 两条路，一个 API

```
             ┌─ 主对话模型自己会看图（deepseek）→ 图片作为 image_url 块，跟她一起读这条消息
图片来了 ────┤
             └─ 主对话模型看不了（hybrid 的本地 LoRA / 引用里的图）
                    → Senses.see()：同一个 DeepSeek API 生成一句描述，塞进消息文本
                         （app.py 把 caption_engine 接到主引擎或 HybridEngine.remote）
```

`perceive(caption=...)` 决定当前消息要不要走描述：主对话已经带图时 `caption=False`，不会重复花 token；
引用消息里一定 `caption=True`。本机 `:8091` 只剩听觉；视觉没有一个本地进程。

## 为什么可行（2026-10-25 实测，deepseek-flash）

| 验证 | 结果 |
|---|---|
| 512×512 纯红图，问颜色 | "红色" |
| 640×320 大字 "BANANA 7" | 读对 |
| 同句**不给图**（对照） | 编了一个不存在的字 |
| 随主对话送图（system+user 里夹 image_url） | 准确说出"绿色草地、白色天空、右边的树、中间的橙色圆球" |
| 延迟 | 0.8–1.6 秒 |
| 输入 token | 800×600≈335；1200×800≈620；>2MP 固定在 ~986（API 自己压） |
| 图片格式 | jpeg / png / gif / webp 都能看 |

两个必须知道的坑：

1. **API 不会自己去抓图片 URL**：`image_url` 给 `http(s)://` 会 400 `Failed to download image`，
   必须本机下载后 base64（`Senses.fetch_image` 已做）。
2. **侧路调用必须 `"thinking": {"type": "disabled"}`**，否则 reasoning 把 `max_tokens` 吃光、`content` 是空的。

## 配置

- `VISION_MAX_IMAGES`（默认 2）：一条消息最多直接交给她几张图；0 表示不看图。
- 只在"她在意的消息"上才取图（私聊、@她、她参与的群），旁听的群消息不下载、不上传。
- 图片会离开本机进 DeepSeek（聊天文字本来就在发）；提示词里保留了"不要猜图里人的身份"。

端到端（真 API）：生成一张有明确内容的图，`media=[{"data": jpeg_bytes, "mime": "image/jpeg"}]`
传给 `DeepSeekEngine().generate_json(prompt, media=...)`，看她能不能说出图里有什么；
再发同一句话不带图做对照（不给图时她只会瞎猜）。2026-10-25 实测她准确说出了草地、树和橙色圆球。
